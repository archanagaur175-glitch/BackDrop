# BackDrop — Architecture

This document records the technical design of BackDrop and serves as the audit trail for every CI self-heal cycle. **The definitive source of truth for the build is `build.yml`; this doc explains why decisions were made.**

---

## 1. Stack decisions (ADR summary)

| Concern | Decision | Rationale |
|---|---|---|
| UI framework | **WinUI 3** (Windows App SDK **2.1.3**) | Mica/Acrylic first-class, `MediaPlayerElement` is MF-backed & hardware accelerated, multi-window is stable. WPF would need fragile DWM interop for the same glass. |
| Runtime | **.NET 10 LTS** (SDK **10.0.302**, pinned in `global.json` + `setup-dotnet`, `rollForward: latestPatch`) | .NET 8 hits EOL Nov 2026 — shipping a new product on it guarantees a forced upgrade mid-life. |
| TFM | `net10.0-windows10.0.26100.0` (min `10.0.17763.0`) | Official WASDK templates' default; min version covers Win10 1809+. |
| Packaging | **Unpackaged, self-contained** (`WindowsPackageType=None`, `WindowsAppSDKSelfContained=true`) → **zip** artifact | Zip is a guaranteed artifact on any runner; no Store identity, no signing dependency for the primary artifact. |
| Secondary packaging | **MSIX** via `makeappx` + self-signed test cert (fail-loud) | Optional; created in `release.yml` only. |
| RID | `win-x64` single-target first | Matrix discipline: add `win-arm64` only after the single target is proven green. |
| NuGet deps | `Microsoft.WindowsAppSDK` 2.1.3, `H.NotifyIcon.WinUI` 2.4.1 (tests: `Microsoft.NET.Test.Sdk` 18.8.1, `MSTest` 4.3.3) | Minimal. No MVVM toolkit — hand-rolled `ObservableObject`/`RelayCommand` in `src/BackDrop.App/Common/`. |
| Dependency locking | `RestorePackagesWithLockFile=true`; lock files generated by the first CI run, then committed; CI then restores with `--locked-mode` | Reproducible builds (§5 of the build protocol). |
| Secrets | PIN hash encrypted with **DPAPI** (`ProtectedData`, CurrentUser) — *not* Windows PasswordVault | PasswordVault depends on package identity, which unpackaged apps don't have; DPAPI needs no identity and works identically packaged or unpackaged. |

**Version pins (verified against NuGet / release metadata, July–Aug 2026):**

- Windows App SDK **2.1.3** (stable May 21, 2026 — ~10 weeks of soak; 2.3.1 adds nothing BackDrop needs)
- .NET SDK **10.0.302** (July 14, 2026 feature band 3)
- `H.NotifyIcon.WinUI` **2.4.1** (depends on WASDK 1.6.x — NuGet unifies up to 2.1.3, no conflict)

## 4. Security design — the PIN gate

1. User opts in via Settings and enters a 4–12 digit PIN.
2. `PinManager` generates a random **salt**, computes `SHA-256(PIN + salt)`, and hands the raw `(salt, hash)` bytes to `SecretVault`.
3. `SecretVault` encrypts the blob with **DPAPI** (`ProtectedData.Protect(..., DataProtectionScope.CurrentUser)`) — keyed to the Windows user's credentials — then base64-encodes it into `settings.json`.
4. On dismissal attempt: decrypt → re-hash entered PIN with stored salt → **constant-time compare** (`CryptographicOperations.FixedTimeEquals`).
5. Recovery is always available: Settings → Remove PIN, or delete `settings.json`. There is deliberately **no** key backdoor while the gate is active; the app never blocks Task Manager or OS-level exits. This feature is opt-in, local, and non-networked by construction.

Caveats (documented, not bugs): DPAPI blobs are tied to the user profile — an admin password reset can invalidate them (recovery path applies); blobs do not roam across machines.

## 5. CI/CD workflow contracts

### `build.yml` (CI) — the gate
- **Triggers:** `push` + `pull_request` on `main`.
- **Steps:** checkout → `actions/setup-dotnet@v4` (pinned 10.0.302, `rollForward: latestPatch`, NuGet cache) → restore (lock-file support; `--locked-mode` added after lock files are committed) → build App Release `x64` → `dotnet test` (Core) → publish `win-x64` → upload artifact.
- **Never** touches signing secrets or publishes. The network-dependent restore step is wrapped in a retry loop.

### `release.yml` (CD) — gated
- **Triggers:** `workflow_dispatch` **or** push of tag `v*` — never bare pushes.
- **Precondition (enforced by process, not by code):** `build.yml` green on `main` before a tag is pushed.
- **Steps:** checkout → setup-dotnet → `dotnet publish -r win-x64 --self-contained true` → zip artifact → `makeappx` MSIX + self-signed `signtool` (fail-loud) → GitHub Release with artifacts attached.

## 6. Zero-fail engineering checklist

- [x] `global.json` pins SDK **10.0.302**; `setup-dotnet` uses the same version with `rollForward: latestPatch`.
- [x] `RestorePackagesWithLockFile=true`; lock files generated by CI, then committed; `--locked-mode` enabled after.
- [x] `TreatWarningsAsErrors` **off** during scaffold (enabled only post-green — §7).
- [x] Explicit `RuntimeIdentifier` `win-x64`, `Platforms` x64 in the App csproj.
- [x] Single-target matrix; `win-arm64` only after green.
- [x] Network steps (restore, asset download) wrapped in retry logic.
- [x] Package validation is fail-loud in `release.yml` (signing/`makeappx` failures abort the release).
- [x] Core unit tests must pass in `build.yml` before release is eligible.

## 7. Self-heal changelog

Every CI fix cycle is appended here (what failed → what was changed → result).

- **Cycle 0 (pre-push code review, not CI):** `MultiMonitorService.cs` referenced `Windows.Graphics.DisplayArea` without the `using` — fixed (would have been a compile error). `MainWindow.xaml.cs` touched `AppWindow` before window activation — deferred until after `Activate()`. `SettingsView.xaml.cs` had a programmatic `PinToggle` feedback loop overriding error messages — restructured to set `IsOn` only after `SetPin` succeeds. Test project pinned to Test SDK 18.8.1 / MSTest 4.3.3 to match runner defaults.
- **Cycle 1 (pre-push hardening round 2, not CI):** Second review pass caught an artifact-path bug (`Platform=x64` sends publish output to `bin/x64/Release/...`, not `bin/Release/...`) — workflow rewritten to build the App project directly, run tests separately, and upload from the correct path. Lock-file sequencing fixed: `RestorePackagesWithLockFile=true` in `Directory.Build.props` so the first CI run generates lock files (no NU1004 gamble), with `--locked-mode` added only after they're committed. Added single-instance mutex (`App.xaml.cs`), window icon (`AppWindow.SetIcon` after activation), PIN-toggle snap-back in Settings, and a restore retry loop. Docs corrected to match code: PIN is 4–12 digits, no `Esc` backdoor, importer accepts 7 container formats, no non-existent AcrylicPanel tuning control.

## 8. Development notes

- **No local builds.** All compilation happens in GitHub Actions (see `build.yml`). The repo never relies on a local SDK.
- **Assets:** `src/BackDrop.App/Assets/BackDrop.ico` is generated by `tools/make-icon.sh` (32×32 32bpp, 4.3 KB). The bundled loop is `default-loop.mp4` (788 KB, Big Buck Bunny trailer, CC-BY 3.0).
- **Adding a video:** drop an H.264 MP4 into `Assets/Videos/` (keep it small — CI artifact budget) or import at runtime via Settings.
